CREAZZY UNIVERSAL AI ORCHESTRATOR

Project Master Context / Continuation Skill

1. PURPOSE

This skill contains the complete project context, requirements, architecture, implementation history, troubleshooting history, Git workflow, testing status, and remaining roadmap for the Creazzy Universal AI Orchestrator.

The agent using this skill MUST NOT rely on memory or assumptions about previous work.

The repository is:

https://github.com/c83491307-gif/Plugins-collectors

Primary working branch:

5. ACCOUNT FAILOVER

If one account:

- reaches quota
- reaches token limit
- receives rate limiting
- becomes unavailable
- authentication expires
- API becomes unhealthy
- provider returns a retryable failure

the system should automatically attempt another eligible account.

Example:

Provider A
    ↓
Account 01
    ↓ quota exhausted
Account 02
    ↓ rate limited
Account 03
    ↓ success

If all accounts of Provider A fail:

Provider A
   ↓
all accounts unavailable
   ↓
Provider B
   ↓
Provider C

The conversation/request should not be lost merely because one account or provider failed.

The router should preserve the request context while changing execution resources.

10. MCP QUALIFIED-NAME BUG

A critical bug was found in:

orchestrator/mcp/aggregator.mjs

The problem was caused by JavaScript object spread ordering.

The implementation effectively created a qualified name and then allowed the spread object to overwrite it.

Incorrect conceptual pattern:

{
  name: qualifiedName,
  ...tool
}

If "tool.name" exists, it overwrites "qualifiedName".

Correct pattern:

{
  ...tool,
  name: qualifiedName,
  server: server.name
}

The explicit "name" property must come AFTER the spread.

This was documented in "SKILL.md".

The documentation includes:

1. Symptom
2. Root Cause
3. Fix
4. Verification
5. Guard Rail
6. Lesson

The general JavaScript lesson:

Object properties appearing later in an object literal override earlier properties.
